# 3.0 feature traceability and baseline

Baseline copied from ReleasePreparation/RunicStorageRules-2.1.3-20261001/source:
Crafting 2.1.2 and its linked Shared source. The source repository's Crafting 1.1.1
is older and contains unrelated uncommitted edits. No baseline source is edited.

| Spec | Existing baseline / gap | 3.0 status |
|---|---|---|
| 1–3 Client-only, independent, mixed installs | 2.1.2 registers shared inventory authority and module handshake | Native proof prerequisite unresolved |
| 4 Craft/upgrade | CraftingRuntime, AuthorityCraftExecution, native Harmony hooks | Must redesign around proven access and exact selected instance |
| 4 Batch | No contract-compliant batch quantity UI established by audit | Pure sequential coordinator/Max estimate implemented and checked; native actions and UI pending |
| 4 Build | AuthorityBuildingExecution/placement policy | Server-dependent baseline; native live-aim path unproven |
| 4 Manual input/fuel | ManualInteractionRuntime/authority execution | Acceptance and uncertainty need native audit |
| 4 Repair | RepairAllRuntime/AreaRepairRuntime | Existing area repair defaults enabled; 3.0 requires disabled |
| 5 Protection/identity | Shared InventorySafety, resource planner | New exact-slice planner, protection and full metadata model checked outside Unity; native serialization/selection adapter pending |
| 6 Index/discovery | ContainerSpatialIndex, preview caches; 20 m range | New 3D range filter/spatial index, 128-source widening and incomplete-search semantics checked; frame scheduling/performance/native events pending |
| 7 Architecture | Mixed integration/runtime/shared authority | Original independent Core library now built; game bootstrap/bindings and authority adapters pending |
| 8 Native access | No production 3.0 client-only implementation | Native handler audit/probe; genuine vanilla-owner busy/idle access, one-Wood mutation, observer and save/reload passed; full adversarial matrix open |
| 9 Optional server | 2.1.2 shared authority is mandatory for nearby path | Separate optional server not implemented; no migration authorized |
| 10–12 Lifecycle/custody/idempotency | Existing shared transaction infrastructure | New pure action/session state machines, exact custody, replay/retirement fences checked; no native/network/crash guarantees claimed |
| 13 Settings/feedback/localization | Existing config/translations preserved | New text/settings not implemented |
| 14 Performance | No evidence for new architecture | Required measurements outstanding |
| 15 Compatibility | Existing shared container/inventory adapters preserved | Authority-specific contracts and mixed installs unproven |
| 16 Verification | 18 bounded release groups in VALIDATION-PLAN.md | Seven prerequisite groups previously exercised; 12 focused core groups passed in this checkpoint; release groups remain open |
| 17 Packaging | Public archives preserved | No release package; intentionally no 3.0 support claims |
| 18 Installation claims | Conditional on tested behavior | Not published |

Broad implementation follows the specification's delivery order. A diagnostic DLL
is not RunicCrafting 3.0 and must never be installed on a normal playing profile.
The new Core DLL is also not an installable gameplay plugin. See CORE-DEVELOPMENT.md
and VALIDATION-REPORT.md for exact implementation and evidence boundaries.
